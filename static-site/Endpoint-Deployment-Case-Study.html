Endpoint Deployment Case Study

A two week investigation into an unauthorized deployment across SOC machines, worked from file path to root cause with no dashboard shortcuts.

case-file

> case.load --desktop-goose

  • Status Closed
  • Duration 2 weeks
  • Classification Internal training exercise
  • Role Rookie Analyst

outcome: case solved

Introduction

This Endpoint Deployment Case Study project was an exercise I completed while working part time with the University of Texas at San Antonio Cyber SOC team. The goal was to test how well part time analysts and interns could investigate an unfamiliar event, rely on their own knowledge, and research what they did not immediately understand.

The exercise began when Desktop Goose appeared on my workstation. A goose ran around the screen, interfered with the mouse cursor, and generated random images and Notepad messages. At first, it looked like a harmless prank, but it became the start of a two week investigation. The task was to determine who deployed it and how it was deployed across SOC machines.

Project Goal

Identify two things: who deployed the program onto SOC machines, and how it reached multiple machines at once rather than just one.

Tools Available

  • Microsoft Defender
  • Splunk
  • Carbon Black
  • DNS / DHCP logs

Method Chosen

After a period of reviewing standard SOC tooling without a clear lead, I shifted toward direct file system analysis, relying on prior hands on experience with Windows file paths and deployment mechanisms from an earlier IT role.

Investigation Timeline

Step by Step

Step 01

Initial Tool Review

Followed the same approach as the rest of the team, checking Microsoft Defender, Splunk, Carbon Black, and DNS/DHCP data for indicators. After a while, this felt like moving in circles with no clear lead.

Step 02

Shifted to File Path Analysis

Instead of continuing to search dashboards, I leaned on past experience with Windows file systems from a prior school district IT role and began tracing the file directly at the system level.

Step 03

Found the SCCM Connection

Reviewing the file's location led to a shared path tied to SCCM (System Center Configuration Manager), a platform used to deploy software and updates across multiple devices at once. This was the moment I identified the how.

Step 04

Reviewed Access Control

I pulled the access control list for the SCCM resource to see which accounts had permission to push files through it. The list returned a broad set of possible users, too many to work through one by one efficiently.

Step 05

Used Active Directory to Narrow the Field

I cross referenced that list in Active Directory, comparing roles, titles, and permissions to find who actually had both the access and the responsibility to run a deployment like this. That narrowed the list to two people connected to endpoint deployments. This identified the who.

Technical Breakdown

The core of this investigation came down to two questions, and each one pointed to a different part of the environment. The how was answered by the file's deployment path: SCCM pushes software and updates to many devices simultaneously, which explained how a single action reached every machine in the SOC rather than just mine.

The who required combining two data sources rather than relying on either alone. The access control list on its own only produced a long list of accounts with permission. It was only after cross referencing that list against Active Directory roles, titles, and responsibilities that the field narrowed down to the people who both could and would have reason to run that kind of deployment.

Resolution

Tier 2 SOC analysts and leadership had worked with the endpoint deployment team to run this as a planned exercise, designed as a challenge for analysts. In the end, I gathered enough evidence to build a realistic case narrative and was one of the few analysts over several years who solved it.

Lessons Learned

  • Tools are valuable, but an investigation still needs a clear hypothesis.
  • File paths and deployment locations can reveal the story behind an incident.
  • Access control lists become far more useful when paired with role and permission context.
  • Endpoint deployment systems can explain how one action reaches many devices at once.
  • A good analyst should know when to step away from dashboards and inspect the system directly.
